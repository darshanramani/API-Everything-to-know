Part 1

How backend APIs work

These ideas apply to every web API, whatever language it's written in.

Step 01

What is a backend API?

Think of an app like a restaurant. You (the frontend) never walk into the kitchen. You give your order to a waiter, who brings back your food.

  • Frontend: what users see, like a website or mobile app.
  • API: the waiter. A fixed set of “orders” the frontend is allowed to place.
  • Backend: the kitchen. Business rules, security and calculations live here.
  • Database: the pantry, where data is stored long-term.
Why separate them? One backend can serve a website, an iPhone app and an Android app at the same time, and the database stays safely hidden behind it.

Step 02

Request and response: the HTTP conversation

Apps and servers talk using HTTP. The rule is simple: the client sends a request, and the server sends back exactly one response.

Underneath, both are just plain text. The animation shows the real text that travels over the network when an app asks for todo number 1.

Client = whoever sends the request (browser, phone app, another server, a Python script). Server = the program that answers.

      Step 05
      
Status codes: how did it go?

      
Every response starts with a three-digit status code. The first digit tells you the category, so you can understand most codes at a glance:

      
    
        
  • 2xx: success, it worked.
    • 
        
  • 3xx: redirect, look somewhere else.
    • 
        
  • 4xx: client error. You sent something wrong.
    • 
        
  • 5xx: server error. The server broke.
    •

      Step 06
      
JSON: the language of APIs

      
Requests and responses need a data format that every programming language can read. Almost every modern API uses JSON.

      
JSON looks a lot like a Python dictionary, with a few small differences. When your FastAPI function returns a dict, FastAPI converts it to JSON for you.

      
Remember: JSON is just text. Turning a Python object into JSON text is called serialising; reading it back is parsing.

      Step 07
      
REST: designing clean URLs

      
REST is a set of conventions that makes APIs predictable. The key idea is that the URL names a thing (a noun), and the HTTP method says what to do with it (the verb).

      
    
        
  • Use plural nouns for collections: /todos
    • 
        
  • Put IDs in the path: /todos/5
    • 
        
  • Put filters, search and paging in the query: ?done=true
    • 
        
  • Nest related things: /users/7/todos
    • 
        
  • No verbs in URLs. The method already is the verb.
    •

Part 2
Building APIs with FastAPI
FastAPI turns ordinary Python functions with type hints into a fast, validated, self-documenting API.


  

    

      Step 08
      
Hello, FastAPI

      
A complete API fits in 7 lines. Here's what each piece does:

      
    
        
  1. app = FastAPI() creates your application.
    2. 
        
  2. @app.get("/") is a decorator. It says “when someone sends GET to /, run the function below”.
    3. 
        
  3. The function returns a dict, and FastAPI sends it back as JSON.
    4. 
      

      
Uvicorn is the server program that actually listens for requests and hands them to your app.

      
Why FastAPI? It's fast, it checks your data using type hints, it writes your API documentation automatically, and it supports async. It's one of the most popular Python web frameworks.

    

    

      
main.py → running API

      
main.py


from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def read_root():
    return {"message": "Hello, World!"}

      Step 09
      
Path and query parameters

      
Most endpoints need input. FastAPI reads it straight from the URL and passes it to your function as normal arguments:

      
    
        
  • Path parameters are in {curly braces} in the route. They're required.
    • 
        
  • Query parameters are any other function arguments. Give them a default to make them optional.
    • 
      

      
The type hints matter: item_id: int makes FastAPI convert "42" to 42, and reject "abc" with a clear error.

      
Try it: edit the URL or pick an example.

      Step 10
      
Request bodies and Pydantic validation

      
To accept JSON data (for example to create a user), describe its shape with a Pydantic model, a class with type hints.

      
Before your function runs, FastAPI checks the incoming JSON against the model. If anything is wrong, it replies with 422 and a precise list of problems, and your function never runs. You get validation for free.

      
Notice: Pydantic is helpful, not just strict. The text "24" is converted to the number 24, because that's clearly what was meant.

      
EmailStr needs one extra package: pip install "pydantic[email]".

    

    

      
Validating a request body


class User(BaseModel):
    name: str
    email: EmailStr
    age: int = Field(ge=13, le=120)

@app.post("/users", status_code=201)
def create_user(user: User):
    return user

      Step 12
      
    Dependencies with Depends()
    
      
    Many endpoints need the same things: a database session, the logged-in user, settings. Instead of repeating that code everywhere, you declare what you need and FastAPI provides it. This is called dependency injection.
    

    def get_db():
    db = SessionLocal()
    try:
        yield db          # give it to the endpoint
    finally:
        db.close()        # runs after the response

def get_current_user(token: str = Depends(oauth2_scheme)):
    return decode_token(token)

@app.get("/me/todos")
def my_todos(db: Session = Depends(get_db),
             user: User = Depends(get_current_user)):
    return db.query(Todo).filter_by(owner_id=user.id).all()

    
      
    Bonus: in tests you can swap a dependency for a fake (for example, a test database) without touching your endpoint code.

      Step 13
      
    async and await: don't just stand there waiting
    
      
    Most of a request's time is spent waiting: for a database, a file, or another API. With async def and await, the server can serve other requests during that wait, like a waiter who takes new orders while the kitchen cooks.
    

    @app.get("/report")
async def report():
    data = await db.fetch_all(query)  # server is free meanwhile
    return data

    
      
    Golden rule: inside async def, never call blocking code such as time.sleep() or requests.get(). It freezes the whole server. Use await-able libraries (like httpx or asyncpg), or write a plain def: FastAPI runs plain functions in a thread pool, so they're safe.

      Step 15
      
    Authentication with tokens
    
      
    Most APIs need to know who is calling. A common pattern is the bearer token:
    
      
      
        
    1. The client logs in once with a username and password.
      2. 
        
    2. The server replies with a signed token, often a JWT.
      3. 
        
    3. The client sends that token in the Authorization header on every request.
      4. 
        
    4. The server checks the signature. No valid token means 401.
      5. 
      
    
      
    FastAPI ships helpers for this (OAuth2PasswordBearer, HTTPBearer), and you plug them in with Depends(), exactly like in Step 12.
    
      
    Never store plain passwords. Store a hash (bcrypt or argon2), and always use HTTPS so tokens can't be read in transit.

      From tutorial to real project
      
    
      
      
      🗄️ A real database
      Swap the in-memory dict for PostgreSQL using SQLAlchemy or SQLModel. Use Alembic to manage schema changes (migrations).
      
      
      📁 Project structure
      Split endpoints into files with APIRouter: routers/todos.py, routers/users.py, plus models.py and db.py.
      
      
      🧪 Testing
      TestClient + pytest call your API without a running server. Override dependencies to use a test database.
      
      
      🔐 Settings & secrets
      Keep passwords and keys out of code. Load them from environment variables with pydantic-settings and a .env file.
      
      
      🌍 CORS
      If a browser frontend on another domain calls your API, add CORSMiddleware, or the browser will block the responses.
      
      
      🚀 Deployment
      Package the app with Docker and run it on a cloud service such as Render, Railway, Fly.io or AWS, behind HTTPS.
      
      
      ⏱️ Background tasks
      Send emails or process files after responding, using BackgroundTasks, or a job queue for heavy work.
      
      
      🔄 WebSockets
      For live chat or streaming AI responses, FastAPI supports WebSockets and streaming responses too.
      
    
      
  
      

  
      
    
      Common beginner mistakes
      
    
      
      
      Blocking inside async
      time.sleep() or requests inside async def freezes every request. See Step 13.
      
      
      Leaking private fields
      Returning a user object that contains a password hash? Use response_model to control exactly what goes out.
      
      
      200 for everything
      Returning {"error": "not found"} with status 200 confuses clients. Raise HTTPException(404) instead.
      
      
      Secrets in code
      An API key committed to GitHub is a leaked API key. Use environment variables.
      
      
      No pagination
      Returning 100,000 rows in one response is slow. Add limit and offset (or cursor) query parameters.
      
      
      Global in-memory state
      Our example stores data in a dict. With several worker processes, each one has its own copy. Use a database.
